# FruitTreeScanner 代码改进工作流

适用：修复缺陷、收紧并发/数据完整性边界、减少实测资源开销、局部重构。每轮交付一个可复现、可审查的改进。创建日期：2026-10-01。

## 默认执行与自我迭代

本流程已由仓库根目录的 [AGENTS.md](../../AGENTS.md) 指定为本项目后续代码改进的默认流程。修复缺陷、修改行为、性能优化和重构时，代理应先读取并遵循本流程，用户无需每次重复指定。具体任务中的用户要求决定本轮范围。

自我迭代包含两层：

1. **代码改进闭环：** 定位根因 → 建立回归/基线 → 小范围修改 → 测试 → 复审。测试失败或复审发现阻塞问题时，带着证据回到修复，再次验证；达到本轮完成标准后才关闭该问题。
2. **工作流改进闭环：** 若实际执行暴露验证缺口，例如测试类未纳入 target 却得到汇总通过，就把经验转成具体检查、回归测试或文档规则，验证后用于下一轮。变更需说明触发证据、旧流程漏掉什么、新检查如何防止再次遗漏；不能通过删测试、降低门槛或改变可靠估产约束来消除失败。

每轮记录根因、修改、证据目录、复审发现、剩余风险、结论及下一轮候选。下一轮优先级由严重程度与真实证据决定，不为了“继续迭代”制造无关重构。

普通任务在其目标完成后交付；测试失败和同一目标内的修复/复审无需用户逐轮确认。用户明确要求持续改进时，再在授权范围内逐个推进后续问题。需要用户补充信息、设备或环境条件时，交付已有证据并说明缺口，不能宣称已完成验证。后台定时执行需要另外配置自动化。

Python 入口负责运行检查与记录证据，代理或工程师负责判断、修改和复审。流程按任务范围迭代，不会自行提交、推送或扩大授权范围。

## 直接使用

在仓库根目录执行；需要 Python 3，只有 `preflight` 不需要 Xcode。命令负责验证和记录证据，代码修改由工程师或代理按本轮任务实施。

```sh
# 改动前记录当前 HEAD、已有改动和空白检查；默认也是 preflight
python3 tools/code_improvement_workflow.py preflight

# 查看将执行的命令，不创建日志或运行编译
python3 tools/code_improvement_workflow.py fusion lifecycle --dry-run

# 修复后组合风险关卡；相同测试类只选择一次
python3 tools/code_improvement_workflow.py fusion lifecycle

# 高风险迭代收尾：Domain 独立编译、全部 XCTest、Release 模拟器构建
python3 tools/code_improvement_workflow.py full
```

默认 Xcode：`/Users/reece24/Downloads/Xcode-beta.app/Contents/Developer`。默认测试模拟器：`C722B4F0-E16F-4C14-84A1-8C796DB0FE11`。按次覆盖，不修改全局 Xcode 选择：

```sh

python3 tools/code_improvement_workflow.py storage --simulator YOUR_SIMULATOR_UDID
```

每次执行在仓库外创建独立临时目录，保存 `report.json`、命令日志、`.xcresult`、DerivedData 和开始/结束时的 Git 快照，终端会打印路径。使用 `--output-root /existing/external/directory` 指定留存位置；脚本拒绝仓库内的位置，包括符号链接指向仓库的路径。证据可能包含未提交补丁，分享前检查内容；无需上传到仓库。

跨目标轮或需要长期复核时，先创建仓库外持久目录，例如 `~/Library/Logs/FruitTreeScanner/<iteration>`，再通过 `--output-root` 保存每次原始结果；任务卡、原始副本及复审材料也放在该目录。第 54 轮曾在进程中断后发现 `/private/tmp` 证据已消失，故临时目录不能作为长期留存保证。丢失进程句柄时先检查原进程是否仍在运行；原始结果缺失不能算作通过，需保留源码并重新取得当前证据。不要把根据对话恢复的历史观察伪装成原始结果包。

自定义定向命令也必须每次使用唯一输出目录，保留编译失败和错误原因不对的诊断运行，不能删掉同一路径的结果包再跑。复用 DerivedData 做增量验证前，先冻结并核验该次结果对应的实际加载器、Debug dylib、测试二进制及构建身份；后续构建可能替换这些字节，源码身份相同不代表二进制相同。未及时保留的旧产物明确记为留存缺口，最终交付重新取得并冻结当前实际代码，不把后来的产物冒充旧结果。

## 每轮执行顺序

### 1. 记录问题和基线

先运行 `preflight`，记录真实 HEAD、已有改动、复现输入和用户可见影响。未跟踪文件只记录路径与摘要，不备份内容；Git 补丁不是完整工作区备份。存在 dirty work 时划定本轮文件/函数边界，保留已有改动。

昂贵验证前同时检查本轮新增的未跟踪文本文件；普通 `git diff --check` 不覆盖它们，可对每个已确定的新增文本文件运行 `git diff --no-index --check -- /dev/null <file>`。该命令存在正常内容差异时可返回1，本地带空白错误的对照返回3，须同时核对诊断与退出码，不能只按0/非0误判。已有提交授权时，明确路径暂存后的 `git diff --cached --check` 也须在最终验证前完成。2026-11-03的发布检查曾在暂存后才发现新增文件末尾空行；修正后须保持提交源码身份与最终构建证据一致，不能忽略检查失败或拿旧构建身份冒充当前版本。

读取真实生产调用链：采集 → 帧/深度证据 → 检测与融合 → 结果合成 → 结束流程 → 仓储/导出 → UI 消费者。当前目录有 `Domain/`、`Application/`、`Infrastructure/` 和兼容 `Core/`，以实际调用者为准，不按旧报告猜文件位置。

填写任务卡：

```text
问题 / 用户影响：
复现步骤或输入：
预期行为 / 当前行为：
根因与证据（文件、函数、行号）：
本轮文件/函数边界：
需保留的行为与数据格式：
风险类型 / 验证 profiles：
改动前证据目录：
完成标准：
```

### 2. 选择一个有证据的问题

处理顺序：编译失败、崩溃、数据丢失、跨扫描证据污染、可靠估产误计 → 生命周期/取消/重试错误 → 实测内存与性能问题 → 局部复杂度。

问题要有复现步骤、失败回归、可追踪的错误调用链或测量数据。不要仅因文件长而拆分，不用旧测试数量作为当前通过证据。行为缺陷先加入能失败的关键回归，再修复；纯重构先运行相关测试建立行为基线。

### 3. 明确边界后小范围修改

每轮处理一个根因及其必要调用者，使用 `apply_patch`，保持公共入口和现有设计模式。新增 Swift 文件时检查 Xcode target 的实际 Sources 引用，不能仅放进目录。

高风险变更逐项检查：

- **融合与估产：** 仅 `.fused` 参与可靠产量；`imageOnly`、`cloudOnly`、拒绝/低置信度深度及低置信度 confidenceMap 不能通过 fallback 升级。保留 `zeroYieldReasons`、扫描/置信度/调试诊断。阈值变更要有理由与关键回归。
- **生命周期与并发：** 正常暂停/完成保留同扫描已接纳证据；中断、取消、新扫描拒绝旧结果。检查 identity、epoch、Task 所有权、continuation 唯一终态、取消与提交竞争、重试输入是否冻结。
- **存档与导出：** 保留旧格式读取、原始字节摘要、revision/source 身份核对、manifest 最后发布、写出前后校验与恢复状态。旧 UI 或迟到任务不能删除新操作拥有的源文件或已提交记录。
- **资源：** 保留采样上限，流式/分块处理大 PLY，检查大数组和 GPU 缓冲生命周期。性能收益用 Instruments/真机数据证明，区分 Swift COW 共享与实际复制。

### 4. 按风险验证

| Profile | 场景 | 自动执行 |
|---|---|---|
| `preflight` | 文档/工具入口、改动前基线 | Git 快照，unstaged 和 staged `git diff --check` |
| `quick` | 初步编译检查 | preflight + Domain 独立编译 + Debug 模拟器构建；不运行 XCTest |
| `fusion` | 检测、投影、融合、去重、估产、诊断 | preflight + Domain + 融合/检测/候选/回放/聚类/遮挡/估产/诊断测试 |
| `storage` | PLY、仓储、历史、校准、批量导出 | preflight + Domain + 导出/点云/校准/参数/标签/分享失败测试 |
| `lifecycle` | 采集、暂停、完成、取消、排空、重试 | preflight + Domain + 会话/追踪/证据并发/计划/结束流程/队列/就绪测试 |
| `ui` | UI 和导航 | preflight + Domain + 全部 XCTest；另做 iOS 模拟器交互与渲染走查 |
| `full` | 高风险修复、跨层重构收尾 | preflight + Domain + 全部 XCTest + unsigned Release 模拟器构建 |

测试类清单集中在 [验证入口](../../tools/code_improvement_workflow.py) 的 `PROFILES`，`--dry-run` 展示完整参数。一个 Swift 文件可能含多个测试类，不能只按文件名选择。涉及多个风险时组合 profiles；高风险本轮完成标准包含定向验证、可行的 `full` 和相关人工/设备验收。

所有运行 XCTest 的 profile 在测试前单独记录 `xcrun simctl bootstatus <所选 UDID> -b`，需要时启动该模拟器并等待系统完成启动；失败时保留退出码并停止后续测试/Release。`preflight` 和仅编译的 `quick` 不启动设备。第 60 轮从关机模拟器开始的 full 有 56 项宿主测试缺少 `UIWindowScene`；同一份 App/测试源码在明确启动就绪后 1147 项和 Release 全部通过。该对照支持将启动就绪作为前置条件，但不能证明每个场景缺失都源于冷启动。bootstatus 也不证明 App 的 foreground scene 已可用，场景断言及其失败仍必须保留；不得通过跳过宿主测试、创建假的 scene 或固定延时来取得通过。

新增或调整测试类时同步清单，并检查 `.xcresult` 中关键回归确实执行。脚本核对声明与结果树，要求每个选择的测试类都有实际通过的用例；`full`/`ui` 核对测试目录中所有 XCTest 类。具体关键方法仍须复审结果。重现具体回归时，沿用 dry-run 中的 Xcode 环境与目标，另执行 `-only-testing:FruitTreeScannerTests/ClassName/testMethod` 并指定独立结果包。

### 5. 根据失败证据修复，再独立复审

命令失败立即停止后续关卡，保存原始退出码与日志。定位编译错误或失败断言，修复后重新运行受影响关卡；最后一次代码修改后的证据才有效。

无法连接 CoreSimulator、缺少 Xcode/runtime、中断、结果包不可读都属于验证未完成。解决环境后再运行，不自动 erase/reset 设备，不把重试当成功。已有基线故障与新增故障分别记录，不能绕过失败后给出整体通过结论。

XCTest 通过条件：进程退出 0、结果包可读、`result=Passed`、有实际通过用例、无失败/跳过/expected failure。需接受跳过时人工记录原因和补充验证，脚本保持失败。仅编译成功、空测试集或日志含成功字样不能代替测试通过。

异步存档/导出交互测试先等待生产完成状态或服务返回，再读取文件并独立断言内容和原档保护。临时文件出现或非空不能代表流式写入完成；保留失败原始附件，用明确完成边界修复竞争，不用固定延时、重试到通过或放宽数据断言代替。第 54 轮全量曾读取到刚创建的 0 字节 CSV，而生产分享界面只在服务完成后发布 URL，测试据此改为等待真实分享界面。

页面关闭测试也须等待所断言的业务提交边界：UIKit 控制器消失不证明 SwiftUI `onDisappear` 已提交草稿，`waitForPendingSave` 只覆盖当时已入队的保存。第 64 轮全量有一项旧校准关闭测试读到旧值；保留原失败及全部精确断言，增加有超时的实际提交状态等待后再验证持久化，全量 1194 项通过。不能仅靠等待动画、固定延时或重复执行取得通过。

根校准提交用例另出现过预期0.60却立即读到0.58：打开/滑杆操作应复用等待弹层稳定、核对唯一当前控件的辅助；切换品类等更新后重新确认当前草稿仍在，保留最后一个滑杆不发送结束操作的条件。关闭后等参数仓与settings同时达到预期，再等持久化；保留品类、冻结计划和全部原精确断言。publication/关闭/提交时序附件只记录实际顺序；退出期间也可能结束编辑，不应仅凭附件断言具体由哪个提交回调完成。

检查结果包中的 `runtimeWarnings`。已实际复现的 SwiftUI `Publishing changes from within view updates is not allowed` 表示状态在视图更新期间发布，属于阻塞问题；脚本即使面对全部 Passed 也拒绝验收，并保留原警告证据。其他运行时警告仍完整留存并由复审判断，不能把自动通过解释为所有警告已解决。警告字段不可解析时验证失败。

摘要门禁通过且存在运行时告警时，工作流额外运行 `tools/inspect_runtime_warnings.py`，把结果库中的测试绑定、原始地址、可用符号与源码位置写入 `runtime-warning-evidence.log`。必须与同一结果包的摘要逐条消息及重复次数对账；数据库、schema或证据不可读时停止后续Release，不以空集合代替。零符号但有地址的栈仍是原始堆栈；缺上下文/缺帧须明确标记，不能写成“无告警”。阻塞警告和失败测试仍按原门禁先停止；需要继续归因时，可对保留的结果包单独执行该工具。

告警挂在哪个测试下，只表示报告时所在的测试，不证明根因属于该测试或对应业务控制器。本次SceneKit销毁告警曾被挂在辅助功能查询和覆盖率控制器测试下，须结合原始地址、二进制UUID/offset与时间核对等待链；同一次运行未触发也不代表已经修复。不得仅因出现QoS告警便改调度优先级、把UIKit销毁移到后台或重写渲染信号量。

性能归因还须区分告警、同步调用耗时与实际等待。使用独立框架最小程序和原生产页面作对照，保留检查器与实际加载库；插桩运行与无插桩运行分别记录。测量结果包含探针及诊断器开销，不能跨环境相减冒充优化收益，也不能把最小程序复现解释为排除了全部应用责任。销毁计时须覆盖原始调用返回，内部等待须核对调用者镜像/offset及所属销毁区间；有界缓冲丢记录、缺返回或缺完成回调均记为证据未完成，不能填零。

异步测量样本须绑定实际实例：渲染回调携带稳定renderer身份，在主队列再次核对当前实例后才标记与释放，避免旧回调释放下一样本。完成数按实际销毁返回记录核对，不能只读“样本循环结束”。每次有效运行冻结对应源码、二进制摘要、所需环境与原始结果；注入诊断库时保留原XCTest加载器，先确认关键方法实际执行，启动失败/零测试不能算产品通过或性能结果。

脚本比较开始/结束的 HEAD、Git 补丁、状态与改动文件摘要；工作区改变会使原本通过的关卡改为失败，需要重跑。这仅比较两个时点，验证期间不要并行修改源码。`passed` 只表示所选自动关卡通过，合并结论需要复审。

有条件时由第二位审查者/子代理只读审查本轮 diff，按严重程度给出文件/行号，关注遗漏分支、晚到结果、吞掉错误、兼容格式与关键测试。无阻塞发现也记录尚未证明的部分。阻塞发现回到本轮修复/验证，不叠加无关改进。

### 6. 人工/设备验收，交付结果

原生渲染与辅助功能验证要读取当前呈现层。若遍历同时包含 AX 元素和 UIKit 原始子视图，须依据隐藏祖先和实际列表归属区分退场单元格，不能按待排除的文本过滤。弹层需单独核对字号确实生效，以及打开、关闭后操作入口恢复；只给宿主设辅助字号并截图不足以证明弹层覆盖。调整窗口宽高和 size class 是布局约束检查，不能记为真实场景旋转或 iPad 设备验收。

更换测试模拟器时，先确认真实辅助功能桥接已启用。建档重建首次在Pro模拟器运行时，生产PNG正常而整份SwiftUI AX树为空；读取设备检查配置后发现缺少AccessibilityEnabled、ApplicationAccessibilityEnabled、AuditInspectionModeEnabled，补齐该测试设备检查状态后，同一App/测试源码的13项原断言全部通过。保留设置前后快照和首轮失败，检查配置只作用于选定的测试设备，不复制其他设备的全部偏好，不erase/reset或删档。不能把可见PNG当作AX可用，也不能跳过AX检查、注入假元素或降低可达性断言来取得通过；无法建立真实桥接时明确记为辅助功能验证未完成。

滚动可达性必须计算实际可见区域。带`safeAreaInset`底栏的`UIScrollView`，滚动终点需包含`adjustedContentInset.bottom`，可见矩形需从`bounds`扣除`adjustedContentInset`后转换到屏幕坐标。仅落在窗口或完整scroll bounds内的AX节点仍可能被固定栏覆盖。首页重建曾出现“回调/窗口断言通过，但截图中按钮在分页下面”的假通过；保留该附件，以扣除内边距的可见矩形、实际回调及滚动完成后的原生截图共同验证，不能靠读取AX节点存在或增加固定等待代替。

定位滚动视图不能只取第一个UIScrollView。历史重建曾选到导航栏内部scroll，原图标为底部却未显示末行操作；应以唯一refreshControl、实际内容语义或可见主体确定归属。LazyVStack还可能在滚动后更新contentSize，需等待目标元素真正进入扣除inset后的可见矩形，再截图或激活回调。保留原始错误附件，不能用错误滚动容器的offset或节点存在冒充内容可达。

还需将scroll可见矩形与实际窗口求交。历史行英文AX5曾因固有宽度撑大正文，控件落在scroll.bounds内却已超出窗口，首次回归因此通过而原生图明显裁切；保留该假通过附件，增加窗口交集后重现失败。AX回调可以激活屏外控件，不能代替窗口内真实可见性。
