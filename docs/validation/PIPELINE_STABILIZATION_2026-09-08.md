# 扫描链路收尾修复与验证

## 本轮修复

1. **停止/暂停丢在途证据**：新帧接收门和已接收结果提交规则分开。正常暂停、继续、完成保留证据代次；新扫描、中断、取消继续使旧代次失效。flush 在等待前捕获代次，在结果提交时再次验证。
2. **排空提前返回**：不再把 6×25 ms 后仍在准备的帧当成空队列。等待本代次准备完成，可由取消或队列清空终止；旧等待不能取走新代次队列。增加“取消本次估算”入口，沿用丢弃确认流程。
3. **历史归档占主线程**：将历史稳定匹配与压缩放入后台任务；MainActor 只负责准备和提交快照，提交检查代次、修订号、取消和 teardown。完成估算快照不再重复同步归档。保留原有稳定轨迹规则、归档与采样上限。
4. **校准可追溯性**：结果及校准记录携带匹配上下文，包括实际 FruitsDetector 资源 SHA-256、品种参数、融合/聚类/颜色配置、中央实验参数和算法版本。模型文件按块读取，指纹进程内缓存；参数 UUID 等非算法字段不参与匹配。缺少模型指纹或无法编码配置时不自动应用校准。
5. **校准基线**：结果额外保存校准前的遮挡修正数量与重量；从扫描带入校准记录时使用这些基线，防止对已校准值再计算修正系数。旧记录继续保留，仅兼容的当前上下文可自动应用。
